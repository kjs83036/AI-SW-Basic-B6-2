# 요구 사항 검증 시나리오

이 문서는 도구의 동작과 입력 범위, 호출 횟수, 오류 처리, 저장소 보존을 재현하기 위한 안내입니다. 생성 결과만으로 테스트 성공이나 변경 사실을 추정하지 않습니다.

## 자동 회귀 테스트

README의 운영체제별 `UV_PROJECT_ENVIRONMENT` 설정을 먼저 적용한 뒤, 프로젝트 루트에서 개발 의존성을 포함해 설치하고 테스트를 실행합니다.

```console
uv sync --locked --system-certs
uv run --locked pytest -q
```

테스트는 임시 Git 저장소와 모의 HTTP 응답을 사용합니다. 사용자 API 키와 외부 API를 호출하지 않으며, 기존 저장소에는 커밋하거나 파일을 추가하지 않습니다.

## 실제 Git 저장소에서 초안 만들기

생성하려는 변경과 무관한 작은 임시 저장소를 만듭니다. 기준 커밋에 추적 파일을 먼저 추가하고, 이후 같은 파일을 수정해 unstaged diff를 준비합니다. 실제 API 키는 과제 프로젝트의 `.env` 또는 환경변수에 설정하고 임시 저장소에는 넣지 않습니다. 과제 프로젝트 루트에서 전용 가상환경 설치를 마친 뒤, 임시 저장소에서는 프로젝트 밖에서도 동작하도록 해당 가상환경의 Python을 직접 호출합니다.

```console
git init
git config user.name "Review"
git config user.email "review@example.invalid"
git add app.py
git commit -m "기준 상태"
```

Windows PowerShell:

```powershell
$toolPython = Join-Path $env:UV_PROJECT_ENVIRONMENT 'Scripts\python.exe'
& $toolPython -m output_6_1.main status
& $toolPython -m output_6_1.main diff
& $toolPython -m output_6_1.main commit
& $toolPython -m output_6_1.main pr
```

macOS (zsh):

```zsh
tool_python="$UV_PROJECT_ENVIRONMENT/bin/python"
"$tool_python" -m output_6_1.main status
"$tool_python" -m output_6_1.main diff
"$tool_python" -m output_6_1.main commit
"$tool_python" -m output_6_1.main pr
```

`status`와 `diff` 출력이 현재 unstaged 변경을 가리키는지 확인합니다. 생성된 커밋·PR 초안은 제목 길이와 PR 섹션을 확인하고, stderr에서 API 요청 번호를 확인합니다. 형식 오류로 재요청한 경우 한 명령의 번호가 1회와 2회에서 끝나는지 확인합니다.

실행 전후 `git rev-parse HEAD`, `git status --porcelain=v1`, `git diff --cached`, `git diff`를 비교합니다. 도구의 목적은 텍스트 초안 출력이므로 네 값은 그대로 유지되어야 합니다.

## 안전모드 전송 범위

별도 임시 저장소의 추적 파일에 201줄을 초과하는 ASCII 변경을 만들고 다음 명령을 각각 실행합니다.

Windows PowerShell에서는 앞 절과 같은 `$toolPython`을 사용합니다.

```powershell
& $toolPython -m output_6_1.main commit --safe-mode
& $toolPython -m output_6_1.main commit
```

macOS (zsh)에서는 앞 절과 같은 `$tool_python`을 사용합니다.

```zsh
"$tool_python" -m output_6_1.main commit --safe-mode
"$tool_python" -m output_6_1.main commit
```

확인할 내용은 다음과 같습니다.

- 안전모드 ON에서는 stderr에 원본 줄 수와 최대 전송 줄 수가 표시됩니다.
- 모의 API 응답을 이용한 자동 테스트에서 실제 요청 prompt에 200번째 변경 줄은 포함되고 201번째 변경 줄은 포함되지 않아야 합니다.
- 안전모드 OFF에서는 201번째 변경 줄도 원문 diff에 남습니다.
- 제한은 앞에서부터 원문 200줄을 고르는 정책입니다. 비밀값 마스킹이나 바이트·토큰 단위 제한은 제공하지 않습니다.

## 변경 없음과 수집 범위

깨끗한 저장소, staged 변경만 있는 저장소, untracked 파일만 있는 저장소, unstaged 변경이 있는 저장소, 바이너리 변경만 있는 저장소를 각각 준비해 `status`, `diff`, `commit` 결과를 비교합니다. 현재 지원하는 생성 입력은 unstaged 상태의 추적 파일입니다. 나머지 조건에서 초안 생성 여부와 README에 기록한 바이너리 diff 안내 처리가 일치하는지 확인합니다.

커밋 제목 72자·73자 및 PR 제목 80자·81자 입력을 검증합니다. 앞뒤 공백을 제거한 제목을 Python `len()`의 문자 수 기준으로 판정하는지, 한국어와 영문 혼합 입력에서도 README의 정책과 일치하는지 확인합니다.

## 오류 종료 상태

새 임시 디렉터리에서 전용 가상환경의 Python으로 `-m output_6_1.main status`를 실행하고 Git 오류가 stderr에 `[ERROR]`로 표시되는지, 종료 코드가 `1`인지 확인합니다. 앞 절의 `$toolPython` 또는 `$tool_python`을 사용합니다. API 키가 없을 때의 종료 코드는 외부 호출 없이 실행되는 회귀 테스트로 확인합니다. 잘못된 명령행 인자는 argparse 종료 코드 `2`를 사용합니다.
